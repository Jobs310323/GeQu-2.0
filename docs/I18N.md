# Internationalization

English is the source locale. Keys are authored in English; `ru` is a full peer,
not a fallback. The architectural decisions and their reasons are in
[ADR-006](adr/ADR-006-i18n.md) — this file is how to work with it.

## Layout

```
src/i18n/
  index.ts          i18next init, bundled resources, changeLocale()
  locale.ts         which language, and how that is decided
  migrated.json     files the Cyrillic gate applies to
  locales/en/*.json
  locales/ru/*.json
src/lib/format.ts   every date, number, currency and sort — Intl only
```

Namespaces mirror the information architecture: `common`, `nav`, `today`,
`capture`, `insights`. More are added per section as 11b progresses.

## Using a string

```tsx
const { t } = useTranslation('today');
<h2>{t('state.heading')}</h2>
<p>{t('streak.inARow', { count: streak })}</p>
```

Across namespaces, qualify: `t('common:action.close')`. Declare every namespace
a component reads: `useTranslation(['common', 'nav'])`.

## Rules

**Never format inside a translation.** Numbers, dates and money go through
`lib/format.ts`, or through i18next's `{{value, number}}` — which is
`Intl.NumberFormat` underneath. A translation containing `6.5` is wrong in
Russian, where it reads `6,5`.

**Never sort text with a bare `.sort()`.** Use `compareText` from
`lib/format.ts`; code-point order puts `ёлка` after `яблоко`.

**Never translate the user's own words.** Task text, journal entries, habit
names, tags: these pass through untouched, in every locale.
`Today.test.tsx` asserts this for a task.

**Plurals go through `count`.** i18next picks the category from
`Intl.PluralRules`. Russian takes `_one` / `_few` / `_many` / `_other`; English
takes `_one` / `_other`. Never hand-roll the selection, and never reuse `count`
as an ordinary parameter name — it triggers plural lookup, so a non-plural
sentence that interpolates a number wants a different name (`hits`, `days`).

**A string used as a discriminant is a bug.** The command palette compared
`action.group === 'Создать'` — a display string doing load-bearing work, so
translating the heading would have silently disabled quick capture. Groups are
ids now.

## The gate

`npm run check:i18n` runs in CI and does five things:

| Check | Catches |
|---|---|
| Key parity | a key added to one language and not the other |
| Plural forms | a locale missing a category `Intl.PluralRules` requires |
| Interpolation parity | a translator dropping `{{count}}` |
| Unused keys | a key nothing references |
| Cyrillic escape | Russian creeping back into a finished file |

Each has been deliberately broken to confirm it fails — the Phase-6 lesson,
where a lint config silently failed to parse and reported zero findings.

### `migrated.json`

The Cyrillic check only applies to files listed there. That is what makes the
migration incremental: a finished screen is protected while the remaining ~110
files are still Russian literals. **Add a file only when it is actually done.**

A line that is legitimately Cyrillic whatever the interface language — a
language's own name in its own script — is marked with an `i18n-allow` comment
on that line, with the reason.

## Adding a locale

1. `src/i18n/locales/<code>/` with one JSON per namespace.
2. Add the code to `SUPPORTED_LOCALES` and a name to `LOCALE_NAMES` (in its own
   script — someone who landed in a language they cannot read still has to find
   the way out).
3. Import the bundles in `src/i18n/index.ts`.
4. Add the Clerk bundle in `main.tsx`.
5. `npm run check:i18n` names every key still missing.

Plurals need no code. RTL is not supported yet: the layout uses physical
`left`/`right` utilities throughout, and switching them to logical properties is
its own piece of work rather than something to half-do here.

## Migration status

Phase 11a is complete: infrastructure, formatting, the locale switch, the gate,
and the shell — navigation, error boundary, modal, sync chip, command palette
and the whole Today surface — as the reference implementation.

Phase 11b is the remaining pages, largest first: `Gym.tsx` (112 Cyrillic lines),
`Finance.tsx` (93), `UserCard.tsx` (92), `Dashboard.tsx` (73),
`ClinicalTests.tsx` (55), then the rest. `migrated.json` is the live record of
what is done.

Two pieces of 11b are not mechanical and are called out in the ADR:

- **Long-form content** (`lib/knowledge.ts`, `lib/cbt.ts`) moves to
  `src/content/{en,ru}/*.md`, loaded with `import.meta.glob(…, { query: '?raw' })`.
- **Validated instruments** (`lib/clinicalTests.ts`) are not translated at all.
  Published English wording is entered as content; an instrument without
  validated wording for a locale is hidden in that locale, never
  machine-translated.
